# Original v1 experiments — 2026-10-31 (historical baseline)

The measurements below describe the original compiler. The subsequent independent audit retains this evidence and reports current v2 results in [INDEPENDENT_AUDIT.md](INDEPENDENT_AUDIT.md) and [OPTIMIZATION_RESULTS.md](OPTIMIZATION_RESULTS.md). Repeated raw JSON/CSV data is in [benchmarks/audit-2026-10-31](benchmarks/audit-2026-10-31/results.json). The original 258 CX figure is the complete three-iteration circuit after transpilation; the original oracle alone has 72 CX gates.

These are real local CPU simulator results from the implementation session, not hardware measurements or illustrative probabilities. Runtime varies with the machine, interpreter imports, load and dependency versions. Raw HTTP evidence is generated by the committed smoke script; one unedited default result is included in [EXAMPLE_RESULT.json](EXAMPLE_RESULT.json).

The initial miss for the same predicate took 0.464599 ms of circuit compilation and 6.901649 ms of inclusive cache lookup/compile/write time. Hits reported zero compiler time. Recreating the container retained hits through the named cache volume. Multiprocess tests also produced exactly one miss and three hits for simultaneous requests with a fresh temporary cache. Compiler/schema changes generated distinct fingerprints; corruption caused recompilation; lowering cache bounds caused eviction even on hits.

For this tiny domain, direct classical evaluation is dramatically faster than simulated Grover. The cache saves compilation, not Python imports or per-request transpilation. These single-request timings do not establish a general benchmark, and the linear baseline is not an optimized database index. Inclusive timing fields overlap and must not be summed together.

## Resource-bound executions

Both requests used 1024 shots and seed 42, succeeded through the REST API within the default 30-second subprocess deadline, and passed independent classical verification.

| Predicate | Search/work/total | Iterations | Ideal / observed valid | Oracle / full depth | CX gates | Aer ms | Server ms |
| --- | --- | ---: | --- | --- | ---: | ---: | ---: |
| width 8, EQUALS(137) | 8 / 1 / 9 | 12 | 0.999947 / 1.000000 | 2549 / 38138 | 22896 | 478.706 | 3589.643 |
| width 7, EQUALS(9) AND four masks | 7 / 9 / 16 | 8 | 0.995620 / 0.998047 | 1341 / 13202 | 8032 | 836.022 | 2507.912 |

The 16-qubit tree ANDs EQUALS(9) with masks `(1,1)`, `(2,0)`, `(4,0)` and `(8,8)`, and has nine AST nodes. Its full complex-double amplitude vector has 1,048,576 bytes; this estimate excludes process, circuit, transpilation and SDK overhead. The width-8 test uses 8192 amplitude bytes but a much deeper no-ancilla MCX decomposition. These observations motivate separate search-width, total-qubit, iteration, shot, process and timeout limits. They do not guarantee that every allowed tree finishes within the deadline on every machine; expensive requests can receive an explicit timeout.

## Concurrency and compatibility observations

Two simultaneous oracle requests succeeded in the HTTP smoke suite and shared cache hits. Running the browser and two-request HTTP suite concurrently caused an intentional 503 `oracle simulator concurrency limit reached`; running those suites separately passed. This verifies saturation is bounded and visible rather than silently overallocating simulator processes.

All existing public Java interfaces, constructors, collection routes, DTOs and Python Grover files remain untouched. Swagger and collection creation/add/list/delete, KEY search, RANGE and explain endpoints were exercised against the Java 17 deployment with both the extension enabled and disabled. The existing 36 tests remain unchanged and green. No real IBM execution was attempted or modified.

**Existing legacy correctness limitation:** the populated multi-key RANGE smoke returned HTTP 200 with `note: "No match found"`, while reporting two encoded qubits but a three-bit top measurement. Its unchanged `PhaseOracle` expression treats each `x00`/`x01`/`x11` token as a separate Boolean variable instead of a bit-pattern conjunction. Legacy KEY search also retains its existing synthetic `matched_value` behavior. These are pre-existing legacy behaviors, not evidence of correct record-level RANGE search. This extension does not repair those unrelated algorithms and does not claim that these smoke checks establish their mathematical correctness. The new oracle path has its own deterministic phase/ancilla/decoding tests.

## Remaining scientific limits

The mandatory vertical slice and demonstration are implemented. OR cardinality is intentionally unsupported analytically; manual iterations are required. There is no Hamming distance/range AST operator, noise experiment, record-attribute encoding, QRAM, hardware backend, automatic Boolean minimization, or faster-than-classical database result. Cache directories must be trusted application storage. Hard ceilings remain 8 search and 16 total qubits; the one-work-bit-per-node compiler is conservative. These are documented scope/resource limits, not silent fallbacks to a marked-state oracle.
