# PlankDB v0.2.0 — draft release notes

Status: release candidate preparation; no tag, GitHub release or publication has been created.

PlankDB v0.2.0 adds an optional **Quantum Oracle Index** beside the existing key-value APIs. Typed Boolean predicates compile into reversible phase circuits and execute Grover on local Qiskit Aer. The oracle evaluates circuit logic rather than a precomputed matching-state list. Results include real simulator measurements, independent classical verification, circuit resources and separate timing stages.

The local Oracle Lab at **http://localhost:8085/oracle-lab/** lets users explore predicates, amplification and overshooting, inspect Qiskit circuits, compare measurements with a brute-force verifier, and view recorded before/after compiler costs. Persistent QPY templates use versioned identity, checksums, locking, atomic writes and bounded resource usage.

## Measured compiler improvements

For width 4, mask 15, value 9, three Grover iterations, 1024 shots and seed 42, under Qiskit 1.1.1/Aer 0.14.2 with basis `u,cx` and optimization level 1:

| Metric | Original | Optimized |
| --- | ---: | ---: |
| Oracle CX gates | 72 | 14 |
| Full Grover CX gates | 258 | 84 |
| Full circuit depth | 455 | 158 |

The ideal success probability is unchanged. Core simulator timings improved in recorded runs, but warm-cache HTTP server measurements had overlapping variability: no robust end-to-end speedup was established. **No database speedup has been demonstrated.** All-to-all circuit counts are not routed hardware costs.

Recorded evidence includes 906 Aer pipeline samples and 600 cache samples. Original and optimized circuits were checked against a separate classical evaluator using exact statevectors, generated nested predicates, signed amplitudes and clean ancillas. These are executed software tests, not an external certification or hardware validation.

## Run locally

```bash
cp .env.example .env
docker compose build
docker compose up -d
docker compose ps
```

Use `Copy-Item .env.example .env` in PowerShell. Keep an existing private `.env` rather than overwriting it. Set `QUANTUM_EXECUTION_MODE=LOCAL` and `QUANTUM_ORACLE_ENABLED=true` for the demo. No IBM token, paid service, GPU or hardware account is required. Swagger remains at http://localhost:8085/swagger-ui.html.

The extension is disabled when its feature flag is omitted. Its additive endpoints are `/api/rest/v1/oracle/explain` and `/api/rest/v1/oracle/search`; existing collection routes and Java interfaces/constructors remain available.

## Limits and known defects

- The search domain is a bounded virtual unsigned integer register, not arbitrary database storage or QRAM: 2–8 search qubits, with a conservative 16-total-qubit limit.
- EQUALS, BITMASK_EQUALS, AND and OR are supported. General OR requires **manual iterations**; production planning does not enumerate the domain to count its matches.
- The **known legacy RANGE defect is unchanged**: populated multi-key ranges may return HTTP 200 with “No match found” and inconsistent decoded bit widths. Legacy KEY synthetic `matched_value` behavior also remains. Smoke tests verify legacy route availability, not the mathematical correctness of those algorithms.
- Cache directories must remain trusted application storage. Checksums detect corruption and do not authenticate a malicious writer.
- IBM behavior was preserved; real hardware calls were not performed for this candidate.
- The pre-audit full HTTP image is a retained local artifact. Compiler/core/cache comparisons can be reproduced from the frozen original compiler in source; exact replay of the original full server requires its original snapshot/image.
